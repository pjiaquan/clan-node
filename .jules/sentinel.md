## 2025-02-14 - Fix missing password length limits (DoS risk)
**Vulnerability:** Multiple critical authentication endpoints (/login, /reset-password, /users/:id) lacked maximum length validation on the password input, exposing the application to resource exhaustion (DoS) attacks via computationally expensive hashing algorithms.
**Learning:** `PASSWORD_MAX_LENGTH` was defined in `src/auth.ts` but its enforcement was inconsistent across routes, particularly in routes added later or less frequently audited.
**Prevention:** Always enforce both minimum and maximum length bounds consistently across all user input endpoints before passing data to expensive cryptographic operations. Ensure bounds check is conditionally applied for optional fields.
## 2025-02-28 - Cryptographic Modulo Bias in MFA Code Generation
**Vulnerability:** The `createMfaCode` function in `src/auth.ts` generated 6-digit MFA codes by applying a modulo of 1,000,000 directly to a 32-bit random integer (`crypto.getRandomValues(new Uint32Array(1))[0] % 1000000`). This introduced a slight cryptographic modulo bias because $2^{32}$ is not evenly divisible by 1,000,000.
**Learning:** Using modulo on a random integer directly introduces bias if the maximum value is not a multiple of the modulus. The lower numbers have a microscopically higher chance of appearing.
**Prevention:** Implement rejection sampling. Calculate the highest clean multiple of the modulus below the maximum possible value of the random generator (e.g., $4,294,000,000$ for a $1,000,000$ modulus on a 32-bit integer). In a loop, generate a random number and discard it if it is equal to or greater than this calculated threshold.
